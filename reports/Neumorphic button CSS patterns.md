# Code soft buttons with dual shadows

People code neumorphic / Soft UI buttons with **two opposing `box-shadow` layers**—a darker cast shadow at positive offsets (bottom-right) and a lighter highlight at negative offsets (top-left)—on a fill that usually matches the parent surface. That **neumorphism.io-style dual-shadow formula** is the raised, surface-matched treatment used for secondary and social controls; pressed states reuse the same pair with `inset` on both layers. Soft login screens then split the primary **Create Account** CTA into a different family: a colored (sometimes gradient) fill with either gray dual shadows kept under the brand color, **brand-tinted soft elevation** via `color-mix`, or a Soft UI kit’s single-direction soft drop shadow that is not true extrusion. For a UI kit Soft button treatment, ship the surface-matched raised recipe as the default Soft control and a separate primary/accent modifier for colored soft CTAs—do not force both jobs into one shadow token.

## Raised Soft UI starts from neumorphism.io’s dual-shadow formula

The concrete raised pattern generators and tutorials emit is always the same three declarations: matching `background`, soft `border-radius`, and a dual `box-shadow`. On [neumorphism.io](https://neumorphism.io/), the default raised export for surface `#e0e0e0` is **`box-shadow: 20px 20px 60px #bebebe, -20px -20px 60px #ffffff`** plus `border-radius` and that same background—the dark layer sits at `+distance` on both axes and the light layer at `-distance`, sharing one blur. The official generator derives those hexes by luminance math: **`darkColor = colorLuminance(color, intensity * -1)`** and **`lightColor = colorLuminance(color, intensity)`**, then assembles `box-shadow: ${x}px ${y}px ${blur}px ${darkColor}, ${-x}px ${-y}px ${blur}px ${lightColor}`, optionally prefixing both layers with `inset` for pressed shapes ([adamgiebl/neumorphism Configuration.js](https://raw.githubusercontent.com/adamgiebl/neumorphism/master/src/Configuration.js)). Distance maps to X/Y offsets; Blur maps to the shared blur radius and is linked at **blur ≈ 2 × distance** by default; Intensity (default **0.15**) scales how far shadow hexes move from the surface ([utils.js](https://raw.githubusercontent.com/adamgiebl/neumorphism/master/src/utils.js)). Clones such as Tezmy and Alion emit the same structure—Tezmy’s default on `#e0e5ec` is `14px 14px 28px #bec3c9, -14px -14px 28px #e5e9ef` ([Tezmy Neumorphism Generator](https://tezmytools.com/neumorphism-generator)).

Button-scale recipes compress the generator’s 20/60 demo values. Tutorials cluster around **offset 6–8px and blur 12–16px** on mid-gray bases such as `#e0e0e0` / `#e0e5ec`, with dark shadows near `#bebebe`–`#a3b1c6` and highlights at `#ffffff` ([Frontend Hero](https://frontend-hero.com/how-to-make-neumorphism-button); [Vinish.Dev](https://vinish.dev/add-neumorphism-effect-pure-css); [DEV.to: Joan Peramás](https://dev.to/joanperamas/neumorphism-what-it-is-and-css-examples-l04)). Themesberg’s kit tokens land in the same band: **`$box-shadow-soft: 6px 6px 12px #b8b9be, -6px -6px 12px #ffffff`** and a lighter `3px/6px` pair, on surface `#e6e7ee` ([Themesberg neumorphism `_variables.scss`](https://github.com/themesberg/neumorphism-ui-bootstrap/blob/d17658d0fea92c140b508088f1fca8a50afdd7c4/src/scss/neumorphism/_variables.scss)). Radius for buttons is typically **10–20px** (often `12px`), with `border: none` unless a thin edge is added for contrast ([Frontend Hero](https://frontend-hero.com/how-to-make-neumorphism-button); [CSS-Tricks](https://css-tricks.com/neumorphism-and-css/)).

## Surface-matched raise needs the same fill as the parent

Classic Soft UI is not Material elevation with a floating chip color. CSS-Tricks states the hard rule: **background colors must be the same (or very similar) as the parent**; otherwise the dual shadows read as ordinary drop shadows instead of extrusion from one material ([CSS-Tricks: Neumorphism and CSS](https://css-tricks.com/neumorphism-and-css/)). Smashing Magazine and Frontend Hero repeat that matching fill is required for the extruded look, and Vinish lists same background as one of three required ingredients alongside dual shadows and rounded corners ([Smashing Magazine](https://www.smashingmagazine.com/2022/03/claymorphism-css-ui-design-trend/); [Frontend Hero](https://frontend-hero.com/how-to-make-neumorphism-button); [Vinish.Dev](https://vinish.dev/add-neumorphism-effect-pure-css)). Bases should avoid pure white or black so light and dark shadows have room to differ ([LogRocket](https://blog.logrocket.com/understanding-neumorphism-css/)).

That surface-matched raised plate is how soft-UI auth demos code Google/GitHub-style social and secondary buttons: **`--surface` (or `#e0e5ec`) on the button, dual gray/white shadows, brand color only on the icon or `color`**. CodeFronts’ social Soft UI buttons set `background: var(--surface)` with `-6px/-6px` light and `6px/6px` shade, and flip to inset on `:active` while brand lives in `--brand` ([CodeFronts Neumorphic Soft UI Social Buttons](https://codefronts.com/snippets/css-social-buttons/neumorphic-soft-ui-social-buttons/)). SoftUI CSS’s default `.sui-btn` is the same idea—`background: var(--sui-bg)` and `box-shadow: var(--sui-shadow-raised)` as **`6px 6px 14px` dark / `-6px -6px 14px` light**—and Design-for-AI recommends this style for secondary controls, not the main CTA ([SoftUI theming](https://softui-css.netlify.app/theming/); [designforai.dev](https://designforai.dev/buttons/neumorphic)).

Pressed interaction is almost always the same dual pair with **`inset`**. Canonical `:active` recipes shrink slightly—e.g. `inset 4px 4px 8px …, inset -4px -4px 8px …`—while rest stays raised ([Frontend Hero](https://frontend-hero.com/how-to-make-neumorphism-button); [FreeCsStyles](https://freecsstyles.com/design/neumorphism-button)). Hover usually stays raised and only scales depth up or down; a minority of tutorials put inset on `:hover` instead ([DEV.to](https://dev.to/joanperamas/neumorphism-what-it-is-and-css-examples-l04); [LogRocket](https://blog.logrocket.com/understanding-neumorphism-css/)). Smooth transitions between outer and inset need matching layer counts—Xerobit keeps four layers (outer + inset, unused pair transparent) so `transition: box-shadow` interpolates ([Xerobit](https://xerobit.dev/blog/neumorphism-css/)). Reusable tokens converge on surface, highlight, shade, and optional distance/blur—e.g. Vinish’s `--bg` / `--shadow` / `--highlight`, Quackit’s `--neu-shadow-offset` with `calc(-1 * offset)` and blur `calc(offset * 2)` ([Vinish.Dev](https://vinish.dev/add-neumorphism-effect-pure-css); [Quackit](https://www.quackit.com/html/templates/buttons/neumorphic_button.cfm)).

## Colored Create Account CTAs use a different elevation recipe

When soft login screens show a teal, blue, or indigo **Create Account** pill, they leave true same-as-background neumorphism. Three coded patterns dominate, and only the first two still speak dual-shadow Soft UI language.

**Pattern A** keeps the gray/white dual raise under a solid brand fill. Red Stapler’s login CTA is a borderless pill (`border-radius: 30px`) with `background: #24cfaa`, white text, and **`box-shadow: 3px 3px 8px #b1b1b1, -3px -3px 8px #ffffff`**—hover/active only recolor the fill, not flip to inset ([Red Stapler](https://redstapler.co/css-neumorphic-login-form-design/)). GeeksforGeeks and several CodePens do the same: green or cyan fill plus page-gray dual shadows such as `.3rem/.6rem #c8d0e7` and white highlight, or `5px 5px 15px #a3b1c6, -5px -5px 15px #ffffff` ([GeeksforGeeks](https://www.geeksforgeeks.org/css/neumorphismui-form/); [CodePen jerora98](https://codepen.io/jerora98/pen/qEbzzMY); [CodePen fghty/eYRWjwv](https://codepen.io/fghty/pen/eYRWjwv)). uiCookies’ `.neu-btn--accent` swaps fill/border/text to `--neu-accent` while **reusing surface shadow tokens** for raise and inset press ([uiCookies](https://uicookies.com/snippets/neumorphic-forms-and-login-card/)).

**Pattern B** retints the elevation to the brand. SoftUI’s `.sui-btn-primary` sets `background: var(--sui-primary)` and overrides raised shadows to **`4px 4px 12px color-mix(in srgb, var(--sui-primary) 35%, transparent), -2px -2px 8px var(--sui-shadow-light)`**, with active as inset black soft shade plus inset tinted primary highlight ([softui-css](https://cdn.jsdelivr.net/npm/softui-css@latest/dist/softui.css)). CodeFronts’ Soft UI Button Lab derives both sides from primary via `color-mix(in oklab, primary, #000 30%)` and `… #fff 42%` so the soft raise reads as colored extrusion rather than a gray halo under a chip ([CodeFronts Soft UI Button Lab](https://codefronts.com/design-styles/css-neumorphism/soft-ui-button-lab/)).

**Pattern C** is Soft UI branding without neumorphic extrusion: Creative Tim Soft UI Design System primary buttons use **`bg-gradient-primary`** and a single-direction soft drop such as **`0 4px 7px -1px rgba(0,0,0,0.11), 0 2px 4px -1px rgba(0,0,0,0.07)`**—no white opposing highlight ([soft-design-system.css](https://raw.githubusercontent.com/creativetimofficial/soft-ui-design-system/main/assets/css/soft-design-system.css)). Soft UI Dashboard’s `$box-shadow-soft: 0 20px 27px 0 rgba(0,0,0,0.05)` language is the same Material-soft family ([App Generator Soft UI Dashboard](https://app-generator.dev/docs/templates/bootstrap/soft-ui-dashboard.html)). A fourth camp keeps the CTA surface-matched like social—puikinsh Sign In uses `#e0e5ec` with `8px/20px` dual raise—and some Foolish Developer forks put accent only on hover text color ([puikinsh style.css](https://puikinsh.github.io/login-forms/forms/neumorphism/style.css); [CodePen fghty/VwbgmBm](https://codepen.io/fghty/pen/VwbgmBm)).

## Kits ship Soft as base raised plus a primary modifier

Production Soft / neumorph kits treat these as **one base class and a color variant**, not one shadow for every button. SoftUI documents `<button class="sui-btn">` versus `sui-btn sui-btn-primary` (and success/danger, pill, outline, ghost); CodeFronts uses `.nm-05__btn` vs `--nm-05-primary`; uiCookies uses `.neu-btn` + `.neu-btn--accent` ([SoftUI Buttons](https://softui-css.netlify.app/components/buttons/); [CodeFronts](https://codefronts.com/design-styles/css-neumorphism/soft-ui-button-lab/); [uiCookies](https://uicookies.com/snippets/neumorphic-forms-and-login-card/)). Themesberg keeps soft-gray primaries on dual soft tokens and separates brand social into `btn-facebook` / `btn-github`-style classes ([Themesberg docs](https://themesberg.com/docs/neumorphism-ui/components/buttons/)). Naming is inconsistent—generators emit bare declarations or `.neumorphic`; libraries use `neu-*`, `np-*`, or Bootstrap `btn-*`—but mixin APIs converge on **base color, distance/height, intensity, raised vs inset** ([Tezmy](https://tezmytools.com/neumorphism-generator); [hollandjake emboss](https://raw.githubusercontent.com/hollandjake/neumorphism/master/sass/_functions.scss); [TheSonOfThomp neu mixin](https://gist.github.com/TheSonOfThomp/cdf0ea316a70bd23b6bef388ab13cb73)).

For a Soft button treatment in a UI kit, the practical split is therefore two shadow tokens: **`--soft-raised`** (surface-matched dual outer, with an inset twin for press) for Soft / secondary / social, and **`--soft-cta`** (either Pattern A gray dual under brand fill, Pattern B `color-mix` tinted dual, or Pattern C soft drop under gradient) for Create Account–style primary. Keep focus as a real outline separate from soft shadows; soft edges alone fail non-text contrast checks, which is why kits often add edge or focus tokens alongside `--bg` / `--hi` / `--lo` ([CSS-Tricks](https://css-tricks.com/neumorphism-and-css/); [Xerobit](https://xerobit.dev/blog/neumorphism-css/); [Quackit](https://www.quackit.com/html/templates/buttons/neumorphic_button.cfm)).

## Conclusion

Soft UI button CSS is a dual-shadow extrusion system scaled from neumorphism.io’s distance/blur/intensity math, not a single “soft shadow” utility. The surface-matched raised style and the colored Create Account style share Soft branding but not the same fill–shadow contract: the first requires fill === parent and opposing light/dark layers; the second deliberately breaks that contract for CTA contrast and then either keeps gray duals, retints them with `color-mix`, or drops to Soft UI kit drop-shadows. Implementing Soft in a kit means encoding that fork explicitly—default Soft = raised surface plate; Soft Primary = separate elevation recipe—so authors can place Google-style soft chips and a colored CTA on the same login without pretending both are classic neumorphism.
